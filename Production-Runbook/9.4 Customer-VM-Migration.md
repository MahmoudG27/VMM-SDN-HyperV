# 9.4 Customer VM migration (per VM)

> Tool: **VMM conversion (V2V)**. Source: Microsoft "Convert a VMware VM to Hyper-V in the VMM fabric".
> An alternative tool (Veeam or other) is **to be verified** against the vCenter/ESXi version.
> The Pattern B guard must be running during migration. Creating/deleting VMs doesn't affect UDR (L28 test), but a subnet change would.

## 1. Requirements (Microsoft)

| Requirement | Check |
|---|---|
| ESXi / vCenter **7.0 or 8.0** | 9.1 |
| VM **stopped**, **no snapshots** | Before convert |
| VMware Tools **uninstalled** from the guest | §3 |
| No disks on an **IDE** bus; not on **vSAN**; not a VMware Workstation VM | 9.1 |
| No online conversion | Downtime per VM |
| Max **10** parallel conversions from one ESXi to one Hyper-V host | Waves |
| After conversion, all disks except the OS disk are **offline** (default disk policy) | §5 |
| BIOS VMs with **more than 4 disks**: not all disks attach. Microsoft provides an attach script | §5 |

Linux and FreeBSD guests aren't mentioned on Microsoft's conversion page: **to be verified** at the pilot.
**Firewall alternative:** build a new appliance VM and import the config export, instead of converting.
**CentOS 7/8 are end of life:** they run on Hyper-V but aren't supported. The customer accepts this in writing before conversion (CustomerA: 10 VMs).

## 2. Prepare VMM once (per vCenter)

On MGMT01 (VMM console):
1. Run As account for vCenter.
2. **Fabric → Servers → Add VMware vCenter Server**: computer name, Run As, Finish, Import certificate.
3. **Add VMware ESX Hosts and Clusters**: host status **OK** or **OK (limited)**. If limited: host Properties → Management → Retrieve.

## 3. Prepare the guest

The conversion doesn't remove VMware Tools: remove them before shutdown.

**Snapshot conflict:** take a snapshot before removing Tools, but VMM requires **no snapshots** at conversion. Order: snapshot → remove Tools → verify the guest → **delete the snapshot** → shut down → convert.
The source VM stays powered off for rollback (9.5), now without VMware Tools. Reinstall them only if rollback is used.

| OS | Before shutdown | After conversion |
|---|---|---|
| **CentOS 7/8** | `yum remove open-vm-tools` · `dracut -f --add-drivers "hv_vmbus hv_storvsc hv_netvsc"` · copy `ifcfg-ens192` to `ifcfg-eth0` without `HWADDR` · fstab by UUID | Check `ip a`, disks, services |
| **Ubuntu** | `apt remove open-vm-tools`. Interface names change: check netplan (*to be verified*, not lab-tested) | Check `ip a`, netplan |
| **Windows** | Save the IP config (`ipconfig /all > C:\ip-before.txt`). Uninstall VMware Tools, reboot | The NIC is new ("Ethernet 2") and has lost its static IP: remove the hidden old NIC first (§5.2 step 1), then re-apply the IP (below). Bring data disks online |
| **FreeBSD firewalls** (pfSense/OPNsense) | Remove open-vm-tools. Export the config | NICs change from `vmx*` to `hn*`: reassign interfaces **by MAC** from the console |

```powershell
# Windows guest, after conversion (VM console)
Get-NetAdapter
New-NetIPAddress -InterfaceAlias "Ethernet 2" -IPAddress <same-ip> -PrefixLength 24 -DefaultGateway <subnet .1>
Set-DnsClientServerAddress -InterfaceAlias "Ethernet 2" -ServerAddresses <dns>
```

## 4. Convert

MGMT01, **VMs and Services → Home → Convert Virtual Machine:**

| Page | Value |
|---|---|
| Source | The VM |
| Identity | Same name |
| Configuration | **Generation follows the source firmware:** BIOS → Gen 1, UEFI → Gen 2 |
| Host / Path | Per `03 Migration-Waves.md`, CSV path |
| Networks | Customer VM network + VM subnet |
| Summary | **Don't start the VM** after conversion: §5.1 comes first |

## 5. After conversion

### 5.1 Before first boot (VM off)

Do all of this right after conversion, so no extra shutdown is needed later.

1. NIC: VM network `<Customer>-Net`, the right VM subnet, **static IP = the same IP as in NSX** (NC anti-spoofing), pool `IPP-<Customer>-<Tier>`. Multi-NIC firewalls: one NIC per subnet, in the order of the interface plan.

```powershell
# MGMT01 (VMM PowerShell) – check against View Script
$nic  = (Get-SCVirtualMachine -Name "<vm>").VirtualNetworkAdapters[0]
$pool = Get-SCStaticIPAddressPool -Name "IPP-<Customer>-<Tier>"
Grant-SCIPAddress -GrantToObjectType VirtualNetworkAdapter -GrantToObjectID $nic.ID -StaticIPAddressPool $pool -IPAddress "<same-ip>"
Set-SCVirtualNetworkAdapter -VirtualNetworkAdapter $nic -IPv4AddressType Static
```

2. Applications licensed by MAC or BIOS UUID: both change. Use a static MAC from the source if needed.

```powershell
# MGMT01 (VMM PowerShell) – only if the application needs the source MAC
Set-SCVirtualNetworkAdapter -VirtualNetworkAdapter $nic -MACAddressType Static -MACAddress "<source MAC>"
```

3. Move the VM to the Cloud, set Cost Center and Tag (9.3).
4. BIOS VMs with more than 4 disks: Microsoft's attach script.
5. Gen 2 only: Secure Boot template.

| Guest | Secure Boot |
|---|---|
| Linux | Template `Microsoft UEFI Certificate Authority` |
| FreeBSD (pfSense/OPNsense) | **Secure Boot off** from the start, no trial boot |
| Windows | Template `Microsoft Windows` |

6. Dynamic Memory off for databases and Kubernetes nodes. Checkpoint type Production and `AutomaticStopAction ShutDown` (L21) for all VMs.
7. Time sync: Hyper-V time sync integration **or** NTP, not both. Domain controllers inside customer VMs: NTP only.
8. HA: VM is a clustered role on CSV.

```powershell
# HV0x (host of the VM, VM off, before first boot)
Set-VMFirmware -VMName "<vm>" -SecureBootTemplate MicrosoftUEFICertificateAuthority   # Gen 2 Linux
Set-VMFirmware -VMName "<vm>" -EnableSecureBoot Off                                   # Gen 2 FreeBSD (pfSense/OPNsense)
Set-VMFirmware -VMName "<vm>" -SecureBootTemplate MicrosoftWindows                    # Gen 2 Windows
Set-VMMemory -VMName "<vm>" -DynamicMemoryEnabled $false                              # databases, Kubernetes nodes
Set-VM -Name "<vm>" -CheckpointType Production -AutomaticStopAction ShutDown
Disable-VMIntegrationService -VMName "<vm>" -Name "Time Synchronization"              # only guests that use NTP
```

### 5.2 After first boot (inside the guest)

1. Windows: remove the hidden old NIC (vmxnet3) **before** re-applying the IP (§3). Otherwise Windows reports that the IP is already assigned to another adapter.
   - Any Windows version: Device Manager → View → Show hidden devices → Network adapters → uninstall the greyed-out vmxnet3.
   - Windows Server 2022 / 2025 can also use `pnputil` below. `/remove-device` needs Windows 10 version 2004 or later ([PnPUtil syntax](https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax)), so Windows Server 2019 uses Device Manager.

```powershell
# Windows guest (VM console)
pnputil /enum-devices /disconnected /class Net
pnputil /remove-device "<instance ID of the vmxnet3 NIC>"
```

2. Gateway = the subnet's `.1`.
3. Windows: data disks online.
4. Non-domain Windows VMs use the Public firewall profile: cross-subnet TCP tests need an explicit rule (L24).
5. Linux: `hv_*` modules loaded.
6. Backup and monitoring agents tied to VMware (snapshot/VADP-based backup, VMware agents) stop working. The customer or the provider replaces them.
