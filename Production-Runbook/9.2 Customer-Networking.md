# 9.2 Customer networking

> Run on **MGMT01** (VMM console / VMM PowerShell). Values come from `Customers/<Customer>/01 Networking.md`.
> **Create all subnets at the start.** On a Pattern B customer, a later subnet change triggers L28.

## 1. Rules

| Rule | Why |
|---|---|
| One VM network per customer, on logical network `HNV-PA`, isolation **Hyper-V Network Virtualization** | Overlapping customer ranges are allowed |
| One VM subnet per NSX segment and per isolated network | Same addressing as today |
| **Default gateway = first usable IP (`.1`)**, answered by the distributed router, reserved by VMM | L15 |
| IP pools start at `.2` or later | L15 |
| VM static IP = the same IP as in NSX | NC anti-spoofing |
| A firewall interface can't use the first IP. If it does in NSX, the firewall IP and the gateway in the VMs change | 0.0 §7, L15 |
| Pattern B: no Port ACLs. Pattern A: Port ACLs with Deny-All, verified in NC | L18, L22 |

## 2. VM network, subnets, pools

Console: **VMs and Services → VM Networks → Create VM Network** → Logical network `HNV-PA` → **Isolate using Hyper-V Network Virtualization** → add every VM subnet → **View Script** before Finish.
Then right-click the VM network → **Create IP Pool**, per subnet.

```powershell
# MGMT01 (VMM PowerShell) – compare with View Script, then run
$ln  = Get-SCLogicalNetwork -Name "HNV-PA"
$vmn = New-SCVMNetwork -Name "<Customer>-Net" -LogicalNetwork $ln -IsolationType "WindowsNetworkVirtualization" `
       -Description "PATTERN B: after ANY subnet change run Apply-<Customer>-UDR.ps1 (9.6)"

$tiers = @(
    @{ Tier = "<Tier>"; Prefix = "10.0.0.0/24"; Gw = "10.0.0.1"; First = "10.0.0.2"; Last = "10.0.0.254" }
    # one line per subnet
)
foreach ($t in $tiers) {
    $sv  = New-SCSubnetVLan -Subnet $t.Prefix
    $sub = New-SCVMSubnet -Name "<Customer>-$($t.Tier)" -VMNetwork $vmn -SubnetVLan $sv
    New-SCStaticIPAddressPool -Name "IPP-<Customer>-$($t.Tier)" -VMSubnet $sub -Subnet $t.Prefix `
        -IPAddressRangeStart $t.First -IPAddressRangeEnd $t.Last `
        -DefaultGateway (New-SCDefaultGateway -IPAddress $t.Gw -Automatic) -DNSServer "<customer-dns>"
}
```

The warning goes in the VM network **description at creation**, before UDRs exist. Editing a *subnet* description didn't remove UDRs in the lab, but editing the *VM network* description afterwards wasn't tested.

The VM network's `ExternalId` **is** the NC virtual network resource ID (lab-verified). The Apply script reads it from VMM (9.6), so nobody types it:

```powershell
# MGMT01 (VMM PowerShell)
(Get-SCVMNetwork -Name "<Customer>-Net").ExternalId
```

The resource ID, not the prefix list, identifies the customer: prefixes overlap between customers.

## 3. Firewall patterns

**Pattern A:** create Port ACLs in VMM (Deny-All last, L18), attach to subnets. Test with TCP. Check in NC that the reference matches (L22).

**Pattern B:**
1. Write the desired state into `Apply-<Customer>-UDR.ps1` (9.6). Each route table lists **every other subnet** plus `0.0.0.0/0` (lab-verified, 9.0 §7).
2. **The next hop is always the firewall's IP in the same subnet as the route table.** A subnet with no firewall NIC gets one, or stays an open question with no VMs on it. The external firewall's transit subnet has **no** route table.
3. Prove both directions on paper: a path table in `01 Networking.md`, one row per flow.
4. Apply **after** the firewall VMs exist with their IPs (9.4), and start the guard for this customer before the first backend VM migrates.

Firewall VMs need a NIC per subnet, each with its static IP from that subnet's pool.

## 4. Public IPs: NAT and VIPs

⚠️ **Timing:** a public IP used on our side is advertised by the MUX, while NSX still advertises it. Create public-IP objects **in the cutover window only** (9.5), after NSX stops advertising. Whether a NAT connection advertises its IP immediately is **to be verified**; assume it does. Before cutover, test with a temporary IP from the pool.

Every public IP must be inside `IPP-PublicVIP` (8.6), and the router's inbound filter must accept its /32 (8.7 §5).

| Mechanism | Use | How |
|---|---|---|
| **NAT connection** on the VM network | First public IP: outbound NAT + inbound rules | Console: VM network → Properties → Connectivity → *Connect directly to an additional logical network* → **NAT** → pool + IP. Then **Network Address Translation** tab → Add rule: Name, Protocol (TCP/UDP), Incoming Port, Destination IP, Destination Port |
| **SLB VIP** | Further public IPs (inbound) | VIP template per port/protocol + `New-SCLoadBalancerVIP` (8.7 §6) |

Microsoft's procedure shows **one** IP per NAT connection. Whether one VM network accepts a second NAT connection is **to be verified**, so further public IPs use SLB VIPs here. Microsoft's NAT page lists TCP/UDP per port and doesn't mention "Any".

Fill every tab, then **View Script** before OK (L17). Keep the IDs from View Script for later queries (L19).

```powershell
# MGMT01 (VMM PowerShell) – NAT connection + inbound rule (Microsoft "Set up NAT")
$vmn  = Get-SCVMNetwork -Name "<Customer>-Net"
$pool = Get-SCStaticIPAddressPool -Name "IPP-PublicVIP"
$gwd  = Get-SCNetworkGateway | Where-Object { $_.Model -match "Microsoft Network Controller" }
Add-SCVMNetworkGateway -Name "<Customer>-Net_Gateway" -EnableBGP $false -NetworkGateway $gwd -VMNetwork $vmn
$nat  = Add-SCNATConnection -VMNetwork $vmn -Name "<Customer>-NAT" -ExternalIPPool $pool -ExternalIPAddress "<public-ip>"
Add-SCNATRule -Name "<rule>" -Protocol "UDP" -InternalIPAddress "<firewall-ip>" -ExternalPort <port> -InternalPort <port> -NATConnection $nat
```

```powershell
# MGMT01 (VMM PowerShell) – SLB VIP, backend = the firewall's NIC on the transit subnet (L26)
$lb   = Get-SCLoadBalancer | Where-Object { $_.Service.Name -like "NC" }
$net  = Get-SCVMNetwork -Name "PublicVIP"
$fw   = Get-SCVirtualMachine -Name "<firewall-vm>"
$nic  = $fw.VirtualNetworkAdapters | Where-Object { $_.IPv4Addresses -contains "<firewall-ip>" }
$vipt = Get-SCLoadBalancerVIPTemplate -Name "<template>"
New-SCLoadBalancerVIP -Name "<Customer>-VIP-<octet>-<port>-<proto>" -LoadBalancer $lb -IPAddress "<public-ip>" `
    -LoadBalancerVIPTemplate $vipt -FrontEndVMNetwork $net -BackEndVirtualNetworkAdapters @($nic)
```

Pattern B rules:
- **Every VIP and NAT rule points at the external firewall only** (L26). The DNAT to the backends moves into the firewall config.
- The firewall receives VIP traffic as `<firewall IP>:<port>`, not the public IP, and its DNAT works (lab-verified). So ports must be unique across the customer's public IPs, or the firewall can't tell them apart.
- VIP health monitors are TCP/HTTP only. Leave them out of UDP templates. L11: a VIP is withdrawn if its backend isn't healthy.
