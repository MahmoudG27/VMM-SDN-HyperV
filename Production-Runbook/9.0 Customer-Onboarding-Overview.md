## 2. Which firewall pattern?

| | Pattern A – native SDN | Pattern B – keep the customer's firewalls |
|---|---|---|
| Design | One VM network, one subnet per tier, **Port ACLs** | One VM network, one subnet per tier, **user-defined routes (UDR)** per subnet, next hop type `VirtualAppliance` = the firewall's IP in that subnet |
| Who filters | NC Port ACLs (VFP on the hosts) | The customer's firewall VMs |
| Tool | VMM | **NC PowerShell only** (VMM has no UDR support): Microsoft "Use network virtual appliances on a virtual network" |
| Port ACLs | Yes, with an explicit Deny-All (L18) | **None** on Pattern B subnets: a second, conflicting layer |
| Extra operations | None | 9.6: Apply script + guard, because of L28 |

In SDN, all subnets of one VM network are routed by the distributed router (the first IP of each subnet, implemented in VFP on every host). They are **not** isolated by default. A customer whose NSX subnets were separated by a firewall VM loses that separation unless Pattern A or B is applied.

## 7. Pattern B lab results (facts, source: lab, 31 Oct 2026)

1. A Windows VM with IP forwarding and one NIC per subnet forwards traffic between subnets via UDR. VFP doesn't drop it. Disabling forwarding on the appliance stops the traffic: there's no bypass path.
2. `tracert` shows the subnet's `.1` first, then the appliance: the UDR is applied inside the distributed router.
3. UDR in **both directions** (a route table per subnet) is required, otherwise the path is asymmetric.
4. Inbound: VIP → firewall VM (DNAT on the firewall) → backend, with UDR 0.0.0.0/0 on the backend subnet → firewall. The path is symmetric and works. The firewall's own subnet has **no** UDR.
5. **T1:** with a route table holding `0.0.0.0/0` only, traffic to another subnet of the same VNet went directly via `.1`, not via the appliance.
6. **T2:** a next hop in another subnet was inconclusive. It isn't used.
7. The firewall receives VIP traffic as `<firewall IP>:<port>`, and its DNAT works (VIP 40.40.40.11 → FW1 10.0.2.10:80 → A1).
8. The VIP health probe through the firewall worked: VIP 40.40.40.11 was advertised with FW1 as backend.
9. L22, L25–L29: table above.

Microsoft facts used by the design ("Use network virtual appliances on a virtual network"):
- Each subnet has **one** route table.
- Routing is by longest prefix match. When a UDR and a system route have the **same** prefix length, the UDR wins.

**Design rules:**
- **Every-subnet rule (lab-verified, T1):** a UDR `0.0.0.0/0` doesn't catch traffic to another subnet of the same VNet, because the /24 system route is longer. Each route table must list every other subnet of the VNet explicitly.
- **Same-subnet next hop (design rule, because T2 was inconclusive):** the next hop is always the firewall's IP in the **same** subnet as the route table. A subnet with no firewall NIC gets one, or stays an open question with no VMs on it. The Apply script refuses anything else.
